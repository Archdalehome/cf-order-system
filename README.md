# 📝 待办清单（Cloudflare Workers + KV）

一个极简的待办清单程序，部署在 Cloudflare Workers 上，使用 Cloudflare KV 存储数据，**无需数据库**。

## ✨ 功能

- **登录页**：用户名 + 密码登录
- **待办事件页**：
  - 折叠显示待办事项，仅显示「主题」和「添加日期」
  - 每个待办固定**一行**显示（不换行）；宽度不足时按优先级隐藏次要标签（添加日期 → 所有者 → 客户 → 金额 → 交期），**生产方简称与订单号（PO#）始终可见**，PO# 过长时以省略号收尾
  - 生产方标签只显示**简称**（悬浮可见完整含义），**观察用户 / 受限观察用户**的待办同样显示；标签为**灰色**中性色
  - 金额标签为**灰色**（中性色，避免与交期的绿/黄/红混淆；观察类用户不显示金额）
  - 管理员可**直接点击**「待确认」待办上的**交期 / 金额**标签，打开弹窗修改 **PO#（主题）/ 交期 / 金额 / 订单文件链接**（进入「进行中 / 已完成」后不可再改）
  - 录入待办时可填写**订单文件链接**与**采购文件链接**（均须以 `http://` 或 `https://` 开头，可留空）。点击 PO# 打开的文件：**管理员 / 可录入用户 / 生产方 / 客户** 打开**订单文件链接**；观察用户 / 受限观察用户的 PO# 始终为纯文本、不可点击。**管理员 / 超级观察者**还可点击待办行右端的**生产方标签**打开该待办的**采购文件链接**
  - 交期标签只显示日期（如 `2026-09-30`）；**待确认 / 进行中 / 已完成**三种状态都按交期着色：已到期/逾期=红、剩余 2 周内=黄、剩余超过 2 周=绿（三种状态配色一致）
  - 点击主题后下拉展开详情（参考 Notion 展示方式）
  - 交期输入框空值时显示自绘提示 `yyyy/mm/dd`（不受浏览器语言影响；有值或聚焦时显示原生日期，Firefox 用原生 `placeholder`）
  - **备注为追加式**：任何用户（含观察用户）都可在待办下添加备注，备注记录作者与时间，**添加后不可删除**
  - 支持标记完成 / 删除待办
  - **「已完成」折叠加载**：为免已完成待办过多拖慢首屏，**默认只显示最新 5 条**，底部出现「**加载更多（还有 N 条）**」按钮，**每点一次再多显示 20 条**；标题「已完成 (N)」始终显示总数
- **用户管理**：
  - 默认管理员 `admin` / `admin`（登录后可修改密码）
  - 管理员可添加 / 删除成员账户，并指定成员角色
  - 管理员可为每个成员添加 / 编辑**备注**：成员列表里**直接点击备注文字**即可弹出编辑框（不显示「备注」字样与按钮，留空即清除备注）
  - 成员列表按**区块**显示：每个成员一个加深底色的独立区块（卡片白 → 成员区块加深 → 内嵌的「客户列表 / 可观察生产方」白底面板），区块之间留空隙，避免几个成员看成一团
  - 每个「可录入用户」拥有独立的待办列表
  - 成员角色支持：可录入用户 / 观察用户 / **受限观察用户**（仅可查看被授权「生产方」的待办）/ **超级观察者**（拥有管理员的全部**待办**功能，但没有「系统设置 / 成员管理 / 生产方管理 / 客户管理」）
- **生产方管理（仅管理员）**：
  - 顶部「生产方管理」按钮打开独立弹窗
  - 生产方为**全局共享**数据，字段为**用户名**、**密码**、**说明**
  - 管理员可添加 / 删除生产方；**用户名不可重复**（也不能与成员账号重名）
  - 添加生产方时会**同时创建登录账号**：生产方用该「用户名 + 密码」登录后，**只能看到指定给自己的（进行中/已完成）待办**（只读）
  - 列表里每位生产方带「**重置密码**」按钮，行内的**「说明」可直接点击修改**（留空即清除说明）；**历史生产方**（早期只有「简称」、没有账号的）第一次重置密码时会自动补建登录账号
  - 其他成员只读（登录后可查询该列表）
- **客户管理（仅管理员）**：
  - 顶部「客户管理」按钮打开独立弹窗，功能与「生产方管理」相同
  - 客户为**全局共享**数据，字段为**用户名**（同时作为客户名称）、**密码**、**说明**；用户名不可重复（也不能与成员 / 生产方账号重名）
  - 添加客户时会**同时创建登录账号**：客户用该「用户名 + 密码」登录后，**只能看到本客户名下的（进行中/已完成）待办**（只读）
  - 列表里每位客户带「**重置密码**」按钮，行内的**「说明」可直接点击修改**（留空即清除说明）；**历史客户**（早期只有客户记录、没有账号的）第一次重置密码时会自动补建登录账号
  - 在「成员管理」中为**可录入用户**分配客户时，下拉选项**直接来自该列表**（已分配的自动排除）

## 👥 角色权限说明

| 角色 | 说明 | 权限 |
| ---- | ---- | ---- |
| 管理员（admin） | 系统默认账户 | 管理成员；查看**所有用户**的待办（含待确认）；**唯一可改变待办状态**；可删除任意待办；可添加备注 |
| 超级观察者（superviewer） | 由管理员在「成员管理」中添加 | 与管理员相同的**待办**功能：查看**所有用户**的待办（含待确认）、**可改变待办状态**、可指定生产方、可修改「待确认」待办（PO#/交期/金额/文件链接）、可删除待办、可添加备注；**但没有**「系统设置 / 成员管理 / 生产方管理 / 客户管理」 |
| 可录入用户（editor） | 由管理员添加 | 录入/删除自己的待办（可用客户由管理员在「成员管理」中从「客户管理」列表里分配）；**不能改变待办状态**；可添加备注 |
| 观察用户（viewer） | 由管理员添加 | **只读**查看所有用户**已确认（进行中/已完成）**的待办；不能录入或修改待办；但**可添加备注** |
| 受限观察用户（restricted） | 由管理员添加，并需逐个授权可观察的「生产方」 | **只读**查看**被授权生产方**名下（进行中/已完成）的待办；未授权的生产方及其待办完全不可见；不能录入或修改待办；但**可添加备注** |
| 生产方（producer） | 由管理员在「生产方管理」中添加（**用户名 + 密码**，自动创建登录账号） | **只读**查看**指定给自己**的（进行中/已完成）待办；其他生产方的待办不可见；不能录入或修改待办；但**可添加备注**；可自行修改密码；列表中点击 **PO# 可打开该待办的「订单文件链接」** |
| 客户（customer） | 由管理员在「客户管理」中添加（**用户名 + 密码**，自动创建登录账号） | **只读**查看**本客户名下**的（进行中/已完成）待办；其他客户的待办不可见；不能录入或修改待办；但**可添加备注**；可自行修改密码；列表中点击 **PO# 可打开该待办的「订单文件链接」** |

### 🏭 生产方与「受限观察用户」使用流程

1. **管理员**在顶部「生产方管理」中添加生产方（字段：**用户名**、**密码**、**说明**；添加后会同时创建该生产方的登录账号）。
2. **管理员**在「成员管理」中新增成员时选择角色 **受限观察用户**；该成员下方会出现「可观察生产方」区块，可为其**添加 / 取消**授权的生产方（下拉选项来自「生产方管理」）。
3. **管理员**将某条待办的状态由「待确认」改为「**进行中**」时，会弹出「指定生产方」窗口，**必须选择**一个生产方（选项同样来自「生产方管理」）；选择完成后待办卡片上会显示该生产方的**简称**标签（鼠标悬浮可见完整含义）。
4. 该受限观察用户登录后，**只能看到其被授权生产方的（进行中/已完成）待办**（页面不再显示「你被授权的可观察生产方：xxx」提示栏）。

### 🏢 客户与「可录入用户」使用流程

1. **管理员**在顶部「**客户管理**」中添加客户（字段：**用户名**、**密码**、**说明**；添加后会同时创建该客户的登录账号）。
2. **管理员**在「成员管理」中为某个**可录入用户**分配客户：该成员下方「客户列表」区块的下拉选项**直接来自「客户管理」**，选中后点「添加客户」即可（已分配的客户不会重复出现在下拉里；全部客户都已分配时下拉会隐藏）。
3. 该成员登录后，在录入框的「客户」下拉中即可直接选用这些客户（下单选客户是录入待办的前置条件之一）。

### 📊 待办状态说明

待办共有三种状态，**新建待办默认为「待确认」**：

| 状态 | 说明 | 可见范围 |
| ---- | ---- | ---- |
| 🟠 待确认（pending） | 新建待办的默认状态 | 仅 **admin** 和 **录入者本人** 可见 |
| 🔵 进行中（doing） | 由管理员确认后进入 | 所有人可见（含观察用户） |
| 🟢 已完成（done） | 由管理员标记完成 | 所有人可见（含观察用户） |

> **状态流转**：只有**管理员 / 超级观察者**可以改变待办状态（通过列表中的状态下拉框）。录入者新建的待办默认「待确认」，需管理员确认改为「进行中」后，观察用户才能看到。
>
> **管理员 / 超级观察者**：待办列表显示所有用户的待办（标注所有者），可通过下拉框改变任意待办的状态，也可删除任意待办。
>
> **生产方下拉的显示时机**：待办行左侧第二个「生产方」下拉**仅在「待确认」阶段显示**（可预先指定）；「进行中 / 已完成」的待办以**灰色简称标签**展示生产方，不再显示下拉（如需修改生产方，先把状态改回「待确认」）。由「待确认」改为「进行中」且未指定生产方时，会弹出「指定生产方」窗口强制选择。
>
> **PO# / 交期 / 金额 / 订单链接的修改**：仅「**待确认**」的待办可修改 —— 管理员直接点击卡片上的**交期**或**金额**标签（可点击的标签带浅色描边、悬浮变蓝），在弹窗里同时修改 **PO#（主题）/ 交期 / 金额 / 订单文件链接**（链接可留空以清除）；状态进入「进行中 / 已完成」后不可再改。
>
> **订单 / 采购文件链接**：录入待办时可以填写（均须以 `http://` 或 `https://` 开头，可留空）。
> - **订单文件链接**：**管理员 / 可录入用户 / 生产方 / 客户**的列表里，PO# 会显示为链接，点击在新标签页打开该订单文件（不会触发展开/折叠）。
> - **采购文件链接**：录入时可填写并随待办保存；**管理员 / 超级观察者**的列表里，待办行右端的**生产方标签**会变成可点击链接，点击即在新标签页打开该采购文件（其他角色页面仍是普通标签）。
> - **观察用户 / 受限观察用户**：列表里 PO# 一律为纯文本，不可点击。
>
> **可录入用户**：仅能看到自己的待办（含待确认），状态为只读徽章，可添加/删除自己的待办。
>
> **观察用户**：待办列表显示所有用户**非待确认**的待办（标注所有者），添加框、状态下拉、删除按钮均隐藏，但可在任意待办下添加备注。
>
> **备注规则**：所有用户（含观察用户）均可添加备注，备注为追加式，记录作者与时间，添加后不可删除。
>
> **交期配色**：**待确认 / 进行中 / 已完成**三种状态的待办**使用同一套交期配色** —— 当前日期 **≥ 交期**（已到期/逾期）显示**红色**；剩余 **0~2 周**（1~14 天）显示**黄色**；剩余**超过 2 周**（>14 天）显示**绿色**。

## �🚀 部署步骤

### 1. 安装依赖

```bash
npm install
```

### 2. 登录 Cloudflare

```bash
npx wrangler login
```

### 3. 创建 KV 命名空间

```bash
npx wrangler kv:namespace create TODO_KV
```

命令会输出类似：

```
[[kv_namespaces]]
binding = "TODO_KV"
id = "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

将输出的 `id` 复制到 `wrangler.toml` 中替换 `REPLACE_WITH_YOUR_KV_NAMESPACE_ID`。

### 4. 本地开发调试（可选）

```bash
npm run dev
```

浏览器打开 `http://localhost:8787`，使用 `admin` / `admin` 登录。

> 本地调试时 wrangler 会使用本地模拟的 KV，不会影响线上数据。

### 5. 部署到 Cloudflare

```bash
npm run deploy
```

部署成功后会得到一个 `https://cf-todolist.<你的子域>.workers.dev` 地址，直接访问即可。

### 6. 方式二：手动上传（不用命令行）

适合不想装 wrangler / 没有本地 Node 环境，直接在 Cloudflare 控制台里粘贴代码的情况。

**① 先把两个源文件压成一个文件**（控制台编辑器只接受单文件）：

```bash
npx --yes esbuild@0.24.0 src/index.js --bundle --format=esm --target=es2022 --minify --charset=utf8 --legal-comments=none --outfile=dist/worker.js
```

生成 `dist/worker.js`（约 108KB，单文件 ES Module；`--charset=utf8` 保留中文不转义，否则体积会翻倍）。

**② 控制台创建 KV 命名空间**：`Storage & Databases` → `KV` → `Create namespace`（名称如 `TODOLIST_KV`）→ 记下 **Namespace ID**。

**③ 创建 Worker**：`Workers & Pages` → `Create` → `Worker` → 起个名字（如 `cf-todolist`）→ `Deploy`。

**④ 粘贴代码**：进入该 Worker → `Edit code` → 全选删除 → 粘贴 `dist/worker.js` **全部内容** → `Save and Deploy`。

**⑤ 绑定 KV（必须做，否则报错）**：Worker → `Settings` → `Bindings` → `Add binding` → **KV Namespace** →
- Variable name 必须是 **`TODO_KV`**（要和代码里的 `env.TODO_KV` 一致）
- KV namespace 选第 ② 步创建的那个 → `Save`（会重新部署）

**⑥ 访问** `https://cf-todolist.<你的子域>.workers.dev`，用 `admin` / `admin` 登录并**立刻改密码**。

> 以后更新：重新执行 ① 生成 `dist/worker.js` → 回到 ④ 粘贴覆盖 → `Save and Deploy`。

## 🗂️ 数据存储说明

所有数据存储在 Cloudflare KV 中，键结构如下：

| Key                | 说明                     |
| ------------------ | ------------------------ |
| `user:<用户名>`    | 用户信息（含密码哈希、成员备注 `remark`）；**生产方 / 客户登录账号**同样是该结构（`role: "producer"` + `producerId`，或 `role: "customer"` + `customerId` / `customerName`） |
| `session:<token>`  | 登录会话（7 天过期）     |
| `todos:<用户名>`   | 该用户的待办列表（JSON） |
| `customers:<用户名>` | 该成员的客户列表（JSON） |
| `watch:<用户名>`   | 受限观察用户「可观察生产方」的 id 列表（JSON） |
| `producers`        | 全局生产方列表（用户名 + 说明，JSON；对应的登录账号见 `user:<用户名>`） |
| `customerList`     | 全局客户列表（用户名 + 说明，JSON；供「客户管理」与成员分配使用；对应的登录账号见 `user:<用户名>`） |

- 密码使用 SHA-256 加盐哈希存储，不保存明文。
- 会话通过 HttpOnly Cookie 保存，有效期 7 天。

## 🔧 自定义

- **修改默认管理员密码**：登录后通过界面修改即可。
- **修改会话有效期**：编辑 `src/index.js` 中的 `expirationTtl` 和 `Max-Age`。
- **修改端口/名称**：编辑 `wrangler.toml` 中的 `name`。

## 📌 注意事项

- Cloudflare KV 免费额度：每天 10 万次读、1000 次写。个人使用完全够用。
- KV 为最终一致性存储，写入后可能有短暂延迟（通常 < 60 秒），对本应用无影响。
